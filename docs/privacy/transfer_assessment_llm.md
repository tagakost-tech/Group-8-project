# Transfer assessment for an AI provider (outline)

Status: outline for counsel, kept for the record. The AI runs only on a model on SUPPLECO's own server (owner's decision of 16 November 2026): the code can no longer send anything to an outside AI company, so no transfer arises and this assessment is not needed unless that decision is reversed.

The AI is on only when `LLM_PROVIDER` is `openai_compatible` with a server's address and model set (`LLM_BASE_URL`, `LLM_MODEL`). The address must point at this machine or SUPPLECO's private network: every address its host resolves to must be loopback or private, checked at start-up and again before every AI call, and nothing is sent otherwise. No cloud AI service is supported. Below, "a key" means that address and model. With the AI on:

- each use that carries a recipient's data has its own switch: the fit check, the opening line, the email body and reply reading are off by default (`config.py`; reply reading has had its own since step G10). The company-country question (`COMPANY_COUNTRY_AI`, 12 November 2026) is on by default: it still sends nothing without a key and `AI_DPA_REFERENCE`, and it sends no more than the fit check;
- none of them sends anything while `AI_DPA_REFERENCE`, the reference of the provider's processing agreement, is blank, as it is by default (`modules/ai_generator.py`; steps G10, G17);
- every prompt is first stripped of email addresses, phone numbers and the query part of web addresses (`modules/compliance.py`, `scrub_for_ai`). Website text, page addresses and domains can still name a person;
- two uses carry no recipient's data and need no agreement reference. Search ideas have their own switch, off by default. AI company discovery has none: when the continuous loop looks for new searches and search ideas are off or yield nothing, it sends the provider one of its search words (those given to the run, or `TARGET_QUERIES`) to get company names (`modules/loop_orchestration.py`).

What is sent stays on SUPPLECO's own server; how long that server keeps it depends on how the server is set up (Ollama keeps no prompt by default).

## 2. The provider and its terms

- The provider and the model. The code supports one route (`LLM_PROVIDER=openai_compatible`): a server that speaks the OpenAI chat interface, at `LLM_BASE_URL` with the model `LLM_MODEL`, such as Ollama on SUPPLECO's own machine (`docs/DEPLOY.md` section 11). The address must be on this machine or SUPPLECO's private network. No outside processor receives the data and no transfer arises. The questions below apply only if that changes.
- The Art. 28 processing agreement, and its date.
- Whether the provider uses what is sent for its own purposes. A plan that allows this is excluded.
- Whether the provider may store prompts for abuse monitoring, and where.

## 3. The transfer basis (Arts. 44-46)

- Whether the provider participates in the EU-US Data Privacy Framework (adequacy decision of 10 July 2023), as checked on the date of the assessment.
- Otherwise: the standard contractual clauses used, and the assessment of the destination country's law that they require.

## 4. Decision

Counsel's conclusion and date. The agreement's reference goes in the setting `AI_DPA_REFERENCE` (step G17). While it is blank, the code makes no AI call that carries a recipient's data (step G10), and the preflight check (`main.py doctor`) warns whenever a switch that lets an AI see recipients' data is on. The code checks only that the setting is not blank: whoever fills it in records where the signed agreement is filed. While such a switch is on, the footer of each email adds that an AI model running on SUPPLECO's own server helps write the emails and read replies, so no outside AI company receives the data (step G14, notice version 2). With the AI only on SUPPLECO's own server there is no provider agreement to record; whether the `AI_DPA_REFERENCE` gate is still needed is the owner's decision, and the code keeps it until then.
